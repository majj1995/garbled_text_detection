# 断笔切口加长 15%：同位置对照

打开 [index.html](index.html)，从左到右为原字、旧断笔、加长后的断笔。
上批 20 张用户反馈全部明显异常；本次新候选仍需独立人工判断，不继承训练标签。

- 同样的 20 个来源字，锁定原先选中的笔画和切点，只将沿笔画方向的切口长度乘以 1.15。
- 横向宽度、笔端排除、两段面积/长度/支撑、实际 96px 净空与全字可见性检查不变。
- 17 张通过；拎、叛、宝在原位置加长后未通过保护检查，展示旧图并留空，不另选笔画或位置。
- 通过的 17 张中，16 张实际切除像素增加；“脖”仅长度参数变化，像素与旧图完全相同，单独标记，不声称已增强。
- 15% 是连续坐标中的长度变化，栅格化和其他笔画遮挡会使像素面积、可见间距的变化比例不同。
- 其他四类、旧数据及模型保持不变。没有生成训练 manifest、导入训练标签或启动实验重训。

## 为什么不直接重跑原来的随机种子

普通生成接口会返回第一个合格候选。强度变化后，即使种子相同，可能有更早的候选通过，
也可能原候选不再通过，因此会换笔或换位置，影响强度对比。

本脚本从旧 NPZ 的 `before_###` 读取笔画，按旧种子重放到旧记录的 `metrics.attempts`。
此前的候选全部忽略，只检查该次提案；接受前核对笔画序号、切点、局部宽度和 1.15 倍长度。
依然经过当前完整的笔画及合成可见性检查，失败就跳过，不放宽门槛，也不执行旧版本代码。
这是离线的“原接受尝试重放”，不是生产接口的“首个合格候选”采样策略。

独立复核确认：17 张通过检查的图与恢复旧接受提案 RNG 状态后的结果一致。
三个跳过项中，拎、宝在 96px 前景阈值 9 下未通过局部净空检查；
叛在 96px 核心阈值 128 下未通过两段笔画检查。没有把失败图作为新候选发布。

## 文件与复现

- `pairs.jsonl`：20 条原字/旧图/新图配对与跳过记录，保留旧候选编号、度量及图像哈希。
- `candidates.jsonl`、`review-template.jsonl`：仅含 17 个新候选，全部 `REVIEW`、非训练用途。
- `layers/*.npz`：17 组修改前后完整笔画，`images/` 包含新图、mask、96px 输入和旧图副本。
- `run.json`：基线文件哈希、实际代码哈希、依赖版本、跳过项和固定重放方式。
- `candidates.html`：可先独立看通过检查的 17 张，再展开原图；其中“脖”并非新的像素样本。

在项目根目录、匹配本批代码与依赖版本时执行：

```bash
PYTHONPATH=src uv run python docs/previews/replay_break_comparison.py \
  --baseline docs/previews/glyph-breaks-20260910 \
  --output-dir artifacts/break-longer-replay
```

输出目录必须不存在。预期打印
`pairs=20 passed=17 pixel_changed=16 pixel_unchanged=1 skipped=3`；
退出码 **2** 明确表示有跳过项，不是程序崩溃，也不会用其他样本补齐。
所有基线资产先检查哈希，旧 NPZ 重组结果需匹配旧像素哈希。
日期会写入 PNG/NPZ 修改说明，所以跨日期重放时文件哈希可能变化；
比较像素哈希、配对位置和度量时，应使用 `run.json` 对应源码与依赖。

本次重点看 16 张像素实际变化的图，判断增强幅度是否合适；
“脖”的像素不变，另外 3 项已跳过，不必重复计作增强样本。
配对校准不是新的独立样本，也不是生产低误报率或模型效果评估。
