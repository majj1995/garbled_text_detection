# AIGC 中文乱码检测系统设计

## 1. 目标与约束

本项目构建一个面向电商商品图、营销海报和广告素材的中文乱码检测系统。系统直接检查图上的字形证据，避免多模态模型或 OCR 将不存在的汉字自动纠正成最相近的正常文案。

首期检测范围包括：

1. 字形异常：不存在的汉字、缺笔、添笔、断裂、粘连、部件错位、相邻字符融合和严重畸变。
2. 字符串异常：单字均可能合法，但组合明显不符合正常简体中文表达的伪中文。

首期不处理通用错别字、语法润色、广告文案质量、多语言乱码或违法内容审核。合法汉字集合以《通用规范汉字表》一级字表 3,500 个常用字为默认范围；英文、数字、单位、型号和业务白名单不因不在该字表中而自动判为异常。

工程约束如下：

- 语言与环境：Python 3.11，使用 `uv` 管理依赖、虚拟环境和命令。
- 现有 OCR：PaddleOCR 3.2 或更高版本，使用 `PP-OCRv5_server_det` 与 `PP-OCRv5_server_rec`。
- 实验与推理硬件：单卡 NVIDIA L20 48 GB。
- 服务形态：在线 GPU 服务，端到端 P95 目标不超过 1.2 秒，1.5 秒为硬上限。
- 审核策略：精确率优先；证据不足时返回人工复核，不自动拦截。
- 线上乱码异常基率：约 0.1%。
- 输出粒度：图片、文本行和字符三级结果，包含异常字符位置与可解释证据。

## 2. 方案选择

采用“字形开放集检测与语言异常融合为主，OCR/字表规则为辅”的混合方案。

未采用单纯 OCR 加字表规则作为主方案，因为 OCR 的语言先验会把伪字归一化成近似真字。未采用端到端多模态模型直接判定，因为当前真实异常样本只有约 100 张，无法可靠训练和校准一个数据需求更大的黑盒模型。

核心原则是：

- PP-OCRv5 的字符坐标用于定位，不将其最终识别文本作为字形真值。
- 字形分支直接比较字符图像和合法字形原型。
- 组合异常分支使用不接语言纠错器的视觉候选序列。
- 常规 OCR 只提供字符对齐、置信度、Top-K、熵和模型分歧特征。
- 自动拦截必须通过类型专属的多证据门控。

## 3. 系统架构与数据流

请求处理流程如下：

1. API 校验 JPEG、PNG 或 WebP 输入，解码并记录原始尺寸。
2. 将超大图片等比例缩放到长边不超过 2,048 像素，并保存坐标变换。
3. PP-OCRv5 server 检测文字行并进行方向处理和文本识别。
4. 优先复用 PP-OCRv5 的单字符坐标。坐标缺失、字符数不一致或裁剪质量不足时，运行字符提议修正头。
5. 对所有字符裁剪进行一次批量字形编码和合法字原型检索。
6. 对整行文字执行无词典视觉序列解码，并计算语言异常分数。
7. 融合字形、结构、视觉序列、常规 OCR、图像质量和白名单特征。
8. 将字符结论聚合为文本行和图片结论，并回映射到原图坐标。

运行时采用一个服务容器内的两个有界 Worker：

- OCR Worker 使用 Paddle Inference 运行 PP-OCRv5 server，并适配识别头以导出解码前 logits 和 Top-K。
- Glyph Worker 运行新增的字形、结构和无词典序列模型。训练模型使用 PyTorch；稳定后优先导出 ONNX/TensorRT。

两个 Worker 共享请求编排但隔离 CUDA 上下文和显存上限。字符裁剪使用动态批处理，合法字形原型常驻显存。

## 4. 字符定位

PP-OCRv5 单字符坐标是首选字符提议。每个提议经过以下质量检查：

- 字符框位于所属文字行内。
- 字符框顺序与文字方向单调一致。
- 相邻字符框重叠和间隔位于业务校准范围内。
- 字符框数量与识别时间步和连通区域数量不存在严重冲突。
- 裁剪后前景占比、清晰度和有效尺寸达到最低要求。

不通过检查的文字行进入字符提议修正头。该模型预测字符中心、宽度和实例 mask，再与无词典 CTC 时间步通过单调动态规划对齐。修正头主要使用带精确坐标的合成海报训练，并使用少量真实全标图片校准。

## 5. 字形开放集分支

### 5.1 输入与编码

每个字符生成三个同步视图：96×96 RGB 裁剪、前景 mask 和边缘/骨架图。首版编码器采用 ConvNeXt-Tiny；输入视图在编码器前进行通道融合。训练目标包括：

- 监督对比损失：同字不同字体和风格相互接近。
- 分类间隔损失：视觉相似的不同合法字保持可分。
- OOD 能量间隔损失：确定性生成的伪字远离合法字簇。
- 结构辅助损失：预测部件、笔画密度、连通区域和骨架端点属性。

### 5.2 合法字原型库

每个合法字符按字体风格聚类并保留多个原型。首版每字最多保留 8 个归一化向量，总原型数不超过 28,000，可通过单次 GPU 矩阵乘法完成 Top-K 检索。

逐字符输出以下证据：

- 最近合法字及其距离。
- Top-1 与 Top-2 距离间隔。
- 分类能量和最大后验概率。
- 部件与笔画结构冲突分数。
- 与 PP-OCRv5 候选的视觉分歧。
- 字符裁剪质量与定位质量。

仅因字符不在 3,500 字表中不得自动拦截。字形异常必须同时满足高 OOD 分数和结构冲突或持续的视觉识别不稳定，并通过真实业务验证集阈值校准。

## 6. 合法字组合异常分支

组合异常使用无词典 CTC 的视觉 Top-K，不接中文纠错器。对每个高概率视觉候选分别计算：

- 基于业务广告语料训练的字符 n-gram 负对数似然。
- 小型字符 Transformer 的 span 伪似然。

为保证高精确率，只要高概率视觉候选中存在合理的中文解释，就不自动判组合异常。自动判定要求：

- 各字符字形均合法。
- 连续汉字长度至少为 4。
- n-gram 与 Transformer 均判定对应最短 span 异常。
- 不命中品牌、人名地名、促销缩写、型号、单位和中英数字混排规则。

少于 4 个汉字或语言证据冲突时只返回 `REVIEW`。

## 7. 数据方案

### 7.1 真实业务数据

现有图片级标签专门表示中文乱码，可直接用于多实例弱监督：正常图表示所有可见文字应正常，异常图表示至少一个文字区域异常。

真实精标预算控制为 100 张图片：60 张异常图进入开发集，20 张异常图作为锁定字符级测试集，20 张困难正常图进入开发集。其余只有图片级标签的真实异常图只用于图片级评测，不参与字符级训练。60 张开发异常图与 20 张困难正常图按商品、活动、模板和来源进行五折分组；同商品、同活动、同模板和近重复图片只能出现在一个数据折中。

额外构建 500–1,000 个字符裁剪快标样本。系统自动生成裁剪，人工只选择“正常、异常、不确定”，不要求画框。抽样优先级为模型分歧、接近阈值的正常字符和未覆盖字体风格。

### 7.2 确定性合成

合法数据由 3,500 常用字、开源或已授权字体和海报特效组合生成。异常数据从合法字形 mask、字体轮廓或笔画路径出发，执行可追踪的操作：

- 缺笔、添笔、断裂和桥接。
- 部件替换、平移、缩放、旋转和错位。
- 相邻字粘连、字符分裂和两字融合。
- 局部擦除、局部扩散重绘和轮廓畸变。

首期生成 30–100 万异常字符裁剪和 10–30 万海报风格文本行。每个样本保存原字符、异常操作、字符框、mask、随机种子和来源许可。

### 7.3 AIGC 数据

AIGC 采用两种方式：

1. 受控风格化：固定已知正常或异常字形 mask 和位置，只生成材质、光照与背景。
2. 自由缺陷挖掘：使用多个图像生成器批量生成复杂中文海报，由初版检测器筛选后进行人工快速复核。

受控风格化结果必须通过 mask IoU、骨架拓扑和合法字 OCR 一致性过滤。无法证明字形未被改写的结果只能作为图片级弱标样本，不能进入正常字符训练集。

### 7.4 开源数据与许可

开发程序自动下载经审核的数据和字体，并为每个来源保存 URL、版本、哈希、许可证、允许用途和本地路径。首批候选包括 Noto CJK、Hanzi Writer 数据、AnyText/AnyWord-3M、TextSSR 和公开中文场景文字数据。

开源代码许可证不自动覆盖其数据集。商业训练权限不清晰的数据只能用于研究基线或方法验证，不能进入生产模型。任何下载脚本必须支持断点续传、校验和、幂等执行和可选数据源。

## 8. 训练流程

训练按以下顺序执行：

1. 使用全部检测到的真实业务字符裁剪进行无标签自监督适配。
2. 使用多字体合法字和确定性伪字训练字形编码器、原型库和结构头。
3. 使用合成海报训练字符提议修正头和无词典视觉序列模型。
4. 使用真实全标和字符快标数据微调字形边界。
5. 使用全部图片级标签进行多实例学习和困难样本挖掘。
6. 使用真实验证集训练带 L2 正则和非负异常证据系数约束的逻辑回归融合器，并校准 BLOCK 与 REVIEW 阈值。

图片级异常袋只约束“至少一个实例异常”，不自动把袋内最高分字符写回金标。高置信伪标签仅进入下一轮候选池；人工确认前不进入金标集。

## 9. 决策与错误处理

最终状态包括：

- `PASS`：没有字符或 span 超过风险阈值。
- `BLOCK`：满足类型专属的多证据门控并超过高精确率阈值。
- `REVIEW`：证据冲突、低清、小字、遮挡、白名单边界、字符超限或部分模型失败。
- `NO_TEXT`：未检测到满足最低质量阈值的文字区域。
- `ERROR`：输入无法解码或服务内部失败。

主字形模型失败、GPU OOM、字符数超过 100 或阶段超时时，服务必须返回 `REVIEW` 并包含原因码，不得仅凭 PP-OCRv5 或字表规则返回 `BLOCK`。输入格式错误返回不可重试的 4xx；内部暂时性错误返回可重试错误码。

同步 HTTP API 返回：

  "decision": "PASS|BLOCK|REVIEW|NO_TEXT|ERROR",
  "risk_score": 0.0,
  "reason_codes": ["GLYPH_OOD"],

  "text_regions": [
    {
      "polygon": [[0, 0], [1, 0], [1, 1], [0, 1]],

        {

默认不保存业务原图，只记录输入哈希、结构化分数、模型版本、时延和错误码。用于主动学习的抽样回流必须显式开启并遵守业务数据保留策略。

## 11. 性能设计

参考输入为长边不超过 2,048 像素且字符数不超过 100 的单张图片。首先在 L20 上建立 PP-OCRv5 server 的独立 P50/P95 基线。新增字形和语言模块的 P95 增量目标不超过 450 毫秒。

端到端验收目标：

- P95 不超过 1.2 秒。
- 硬超时不超过 1.5 秒。
- 分别报告并发 1、2、4、8 时的 P50、P95、P99、QPS 和显存峰值。
- 连续 10,000 请求不得发生未恢复 OOM。

首期优先准确率。性能不达标时依次采用 FP16、字符动态批处理、原型矩阵常驻显存、ONNX/TensorRT 导出和模型蒸馏；不得通过跳过可疑文字区域满足时延。

## 12. 评测与验收

线上异常基率约为 0.1%，因此自动拦截精确率必须按真实基率计算：

`Precision = prevalence × recall / (prevalence × recall + (1 - prevalence) × FPR)`

评测集包括：

- E1 真实异常集：60 张字符级开发异常采用五折 out-of-fold 预测，20 张字符级异常保持锁定测试，其余约 20 张仅有图片级标签的异常只参与图片级评测。
- E2 正常回放集：最低 10 万张，推荐 50–100 万张现网正常图，无需字符框。
- E3 字符金标与合成压力集：真实字符级标注加 10 万以上可控异常样本。
- E4 系统可靠性集：坏图、超大图、无文字、字符超限、超时和 Worker 重启。

阶段门槛如下：

| 阶段 | 正常图 BLOCK FPR | 真实异常 OOF Recall | 其他要求 |
| --- | ---: | ---: | --- |
| MVP 离线 | ≤ 0.01% | ≥ 40% | 字形方案优于 OCR/字表基线 |
| 试点上线 | ≤ 0.0025% | ≥ 50% | 0.1% 基率下 BLOCK Precision ≥ 95% |
| 生产扩量 | 持续满足试点门槛 | 在不降低精确率下提升 | 按品类、字体和生成器分层放量 |

字符级报告定位 Precision/Recall、IoU≥0.5 的字符框匹配、各异常类型召回和 Wilson 置信区间。另行报告 REVIEW 率，不能将 REVIEW 计入 BLOCK 精确率或正常图误报。

## 13. 技术栈与仓库约定

- 环境与打包：Python 3.11、`uv`、`pyproject.toml`、锁文件。
- 训练：PyTorch、torchvision、scikit-learn。
- OCR：PaddleOCR、PaddlePaddle、PP-OCRv5 server。
- 图像与数据：OpenCV、Pillow、NumPy、PyArrow/Parquet。
- API：FastAPI、Pydantic、Uvicorn。
- CLI：Typer。
- 测试与质量：pytest、pytest-cov、Ruff、mypy。
- 推理优化：ONNX Runtime 和 TensorRT 作为第二阶段优化，不阻塞首个准确率 MVP。

代码模块边界为：配置与数据清单、数据下载与许可、合成生成、OCR 适配、字符定位、字形模型、语言模型、融合决策、评测、服务 API 和可观测性。每个模块必须提供纯 Python 接口和独立测试，不允许训练脚本直接依赖在线服务实现。

## 14. 分阶段交付

1. 第 1 周：初始化 Python/uv 工程；完成 PP-OCRv5 server 能力审计、字符坐标/logits 适配和 L20 基线。
2. 第 2–3 周：完成数据清单、许可记录、开源资源下载器、确定性伪字生成器、字形原型库和评测框架。
3. 第 4–6 周：完成开放集字形 MVP、字符快标流程、真实业务适配和 OCR/字表基线对比。
4. 第 7–8 周：完成组合异常分支、图片级弱监督、困难样本挖掘和融合校准。
5. 第 9–10 周：完成 FastAPI 服务、L20 性能优化、大规模正常图回放和试点报告。

每个阶段均产出可运行代码、自动化测试、模型或数据版本清单和可复现实验命令。第一阶段不下载许可不明的大型数据集；下载器先实现并审核数据来源清单，再执行受控下载。

## 15. 主要风险与缓解措施

- 合成域差异：AIGC 只做受控风格化，最终阈值只在真实业务数据上校准。
- 真实异常过少：使用确定性伪字预训练、图片级 MIL、五折 OOF 和主动学习回流。
- 艺术字误报：扩大困难正常集，设置字体/品牌白名单并采用多字体原型。
- OCR 自动纠正：使用原始 logits、无词典视觉候选和直接字形原型距离。
- 字符切分错误：复用 PP-OCRv5 字符坐标并增加质量门控和修正头。
- 极低基率导致虚高 Precision：用 50–100 万正常图回放估计 FPR，并按 0.1% 基率折算。
- 开源数据许可：维护逐数据源许可清单；许可不清的数据不得进入生产训练集。
- 运行时模型故障：主模型失败时只允许 REVIEW/ERROR，不允许辅助规则自动拦截。
